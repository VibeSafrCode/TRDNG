## Результат

- Fail-closed risk policy сверяет точные venue/instrument/product/side/sizing,
  требует успешную official-filter validation и настроенные hard caps.
- Valid filter evidence теперь immutable-привязан к exact `MarketOrderIntent` и
  создаётся `MarketOrderValidator`; вручную созданный `Valid` или evidence другого
  clientId/value/venue не разрешает risk decision.
- QuoteNotional ограничен hard quote cap. BaseQuantity ограничен hard base cap и
  estimated notional по положительной свежей reference price; missing/stale/future
  price блокирует решение.
- Production profile по умолчанию `UNCONFIGURED`. Реальные лимиты Founder ещё не
  утверждал. UI использует только явно подписанный
  `SIMULATION PROFILE · MAX 10 USDT · MAX 1 BASE`; он существует только в
  simulation controller и не связан с transport.
- Даже configured `Production` profile запрещён: S2.2 допускает только
  `Simulation`. Для BaseQuantity требуется положительный price-age limit;
  overflow estimated notional перехватывается и блокируется.
- Kill switch стартует `ENGAGED`, блокирует prepare/confirm и разоружается только
  для configured simulation profile. Повторный STOP инвалидирует preparation.
- Prepare создаёт immutable candidate с exact intent/risk decision/token/TTL.
  Confirm сверяет exact token+intent, имеет TTL, single-use и replay/double-click
  protection; результат только `SIMULATION CONFIRMED · NOT SENT`.
- Asset/product/venue/side/value changes инвалидируют confirmation.
- Bounded in-memory audit фиксирует prepare/allow/block/confirm/reject/STOP без
  secret/key/token полей и без файлов/runtime logs.
- Reference price side-aware: BUY использует BestAsk, SELL — BestBid. Audit events
  без intent хранят nullable поля, а не ложные enum defaults.
- UI показывает active venue, product/symbol, simulation limits, крупный STOP/SAFE,
  `ПОДГОТОВИТЬ DRY RUN` и `ПОДТВЕРДИТЬ СИМУЛЯЦИЮ`. Команд отправки/торговли нет.
