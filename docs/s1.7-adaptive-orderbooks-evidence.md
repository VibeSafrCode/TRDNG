# S1.7 adaptive order books — local evidence

Date: 2026-08-30. Branch: `codex/adaptive-orderbooks`. Baseline:
`b7b0e7060f4c00d7fcb072d78f02dfb59be2ee9e`. Status: local implementation
complete; independent audit and Git publication are separate pending gates.

## User result

- BTC/USDT opens by default in the app and deterministic selection fixtures.
- MEXC, Gate and Bybit USDT perpetual cards can all create public book clients.
  MEXC private perpetual trading remains `Blocked`.
- Each card fills its available height and owns automatic/manual depth, a
  fine-grained vertical trackpad step, automatic/manual volume reference and
  four editable HEX bar colors.
- Owner defaults are ask yellow, largest visible ask red, bid blue and largest
  visible bid green. Ask and bid maxima are calculated independently, so both
  visible side maxima reach 100% width.
- A four-pixel safety gap on both sides of the spread row prevents the nearest
  ask/bid text and bars from being clipped by the central control strip.
- Settings are session-only and do not create a hidden preferences file.

## Public data boundary

- Bybit publishes up to 200 captured levels; Gate up to 50; MEXC Spot up to 200.
- MEXC perpetual uses the official credential-free contract catalog and bounded
  public REST depth polling. It validates success/code, version, two non-empty
  uncrossed sides, prices, contract counts, duplicate levels, price tick and
  contract multiplier. Official source checked 2026-08-30:
  <https://mexcdevelop.github.io/apidocs/contract_v1_en/>.
- Startup catalogs use a dedicated 15-second no-redirect/no-cookie HTTP client;
  live MEXC REST market data retains a five-second client. Responses use the
  shared bounded reader.
- One bounded credential-free BTC smoke through the actual clients passed:
  MEXC `BTC_USDT` 200 bids/200 asks, Gate 50/50 and Bybit `BTCUSDT` 200/200.
