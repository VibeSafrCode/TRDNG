## Official contract

Only the official [MEXC Spot V3 API documentation](https://mexcdevelop.github.io/apidocs/spot_v3_en/)
was checked on 2026-08-14:

- `POST /api/v3/order/test`, permission `SPOT_DEAL_WRITE`, weight 1, response
  `{}`; it validates a new order without sending it to the matching engine.
- Parameters equal the new-order contract. MARKET requires exactly one of
  `quantity` or `quoteOrderQty`: BUY uses quote asset spend through
  `quoteOrderQty`; SELL uses base asset amount through `quantity`.
- Signed POST form data uses the exact parameter string for lowercase
  HMAC-SHA256; API key is in `X-MEXC-APIKEY`, `timestamp` is required, and
  `recvWindow` cannot exceed 60000 ms.
- `exchangeInfo` is the source for API trading availability, quote-order market
  support and precision/amount constraints. The adapter never invents values:
  missing/incoherent `OrderFilterSet` evidence cannot authorize a test.

## Implementation and safety boundary

- Dedicated POST builder has no caller-supplied path and creates only
  `/api/v3/order/test`. Existing GET allowlist remains account/openOrders.
- Redirect/cookies remain disabled; one attempt, bounded timeout/cancellation and
  streaming 1 MiB cap remain enforced.
- Authorization requires the exact intent embedded by successful S2.2
  confirmation, exact `ValidatedIntent`, and risk evidence explicitly marked
  `RiskProfileMode.Simulation`; authorization is one-shot. Replay is rejected
  before network.
- Privileges are separated: S3.2 reads only `readonly-api-key`/`readonly-secret`;
  `/order/test` reads only distinct `order-test-api-key`/`order-test-secret`
  identities. A trade-enabled key is never stored under or shared with the
  read-only profile.
- Only MEXC Spot MARKET BUY + QuoteNotional and SELL + BaseQuantity are accepted.
  Other venue/product/side/sizing combinations fail closed.
- Success is `TEST READY · NOT AN ORDER`; errors are masked. Raw exchange text,
  key, secret, signature and signed body do not enter audit/UI.
- No production order/cancel/withdraw/transfer transport exists; no simulation
  journal state changes to Filled. UI adds only a non-interactive masked status.

## Deterministic evidence

Tests cover BUY/SELL mapping, canonical form/signature, exact path, mismatched
evidence, unsupported combinations, replay, stale time, error mapping, redirect,
cancellation, oversized response, no retry, redaction and production-path denial.

Repeat-audit coverage proves order-test calls read only the distinct
trade-permission identities while account reads use only read-only identities.
The internal builder independently rejects wrong side/sizing fields,
non-positive or malformed values and malformed symbols. Its explicit ASCII
fixed-point grammar allows safe trailing zeros but rejects signs, whitespace,
exponents, grouping/comma, missing integer/fraction digits, multiple dots,
leading-zero ambiguity, zero, overflow and values over 64 characters. Intent
decimals use one shared `G29` invariant formatter. Confirmation evidence carries
explicit Simulation provenance.
