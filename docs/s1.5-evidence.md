# TRDNG Stage 1 — S1.5 evidence

Дата: 2026-08-10. Статус: **IMPLEMENTATION / BUILD / PACKAGE PASS; RUNTIME VISUAL OPEN**.

## Результат

- Экран имеет три постоянные независимые колонки в порядке `MEXC → Gate → Bybit`.
- Один canonical selection `asset + product` управляет всеми колонками.
- Каждая колонка показывает собственные venue, symbol, product, status и книгу.
- `FUTURES`: Gate/Bybit поддержаны, MEXC честно `UNAVAILABLE`; `SPOT`: MEXC
  поддержан, Gate/Bybit честно `UNAVAILABLE` с текстом о нереализованном адаптере.
- MEXC, Gate и Bybit имеют отдельные snapshots и ObservableCollections; ликвидность
  не объединяется.
- Общая шкала получает только LIVE-книги выбранного product. При одной книге UI
  пишет `ШКАЛА ОДНОЙ БИРЖИ`, а не создаёт впечатление межбиржевого сравнения.
- Сохранены generation guard, latest-request-wins, detach/dispose и rejection
  устаревших callbacks.
- После аудита все три liquidity tracker объединены в один lifecycle owner;
  selection reset вызывает `ResetAll`, включая MEXC, поэтому поведение уровней
  прежнего актива не переживает APT↔BTC.
- Freshness eligibility учитывает timestamp: warning-age остаётся в шкале,
  stale-age исключается и очищает соответствующие строки. Health timer вызывает
  rebuild только при изменении eligibility mask, не каждые 500 ms.
- Consensus использует тот же state/timestamp/freshness contract: warning
  допустим, stale и другой product исключаются; без eligible книг немедленно
  показывается `ЭВРИСТИКА: НЕТ ДАННЫХ`, включая selection reset.

Аудитор отдельно исправил и проверил три риска: reset MEXC liquidity tracker;
исключение stale-книг из общей шкалы с rebuild только при переходе eligibility;
исключение stale-книг из consensus с немедленным no-data reset.
