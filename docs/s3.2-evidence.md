## User result

TRDNG now has a fail-closed deterministic foundation for reading MEXC Spot
account balances and current open orders after a separate credential gate. This
sprint did not enter credentials or make an authenticated request.

## Official contract

Only the official [MEXC Spot V3 API documentation](https://mexcdevelop.github.io/apidocs/spot_v3_en/)
was used, checked 2026-08-14:

- Server time: `GET /api/v3/time`, `serverTime` milliseconds.
- Signed endpoints require `timestamp`, optional `recvWindow` (default 5000,
  maximum 60000), lowercase HMAC-SHA256 of exact parameters, signature in the
  query/body, and API key in `X-MEXC-APIKEY`.
- Account: `GET /api/v3/account`, permission `SPOT_ACCOUNT_READ`.
- Open orders: `GET /api/v3/openOrders`, permission `SPOT_DEAL_READ`; this client
  requires one explicit symbol.
- Timing and errors include timestamp outside window (`700003`), no permission
  (`700007`), invalid key (`10072`), rate limit (`429`) and service failures.

## Implementation

- Stable canonical query ordering/encoding and official published HMAC vector.
- Signed wrapper has redacted `ToString`; underlying request is internal. API key
  is header-only. Signed URL, signature, key and secret never enter product audit,
  UI or exception messages.
- Separate validated Keychain identities for read-only API key and secret, read
  only through `ICredentialVault` and bounded `SecretLease` lifetimes.
- Time offset uses request midpoint, bounded RTT and explicit freshness. Missing,
  stale, invalid or overflowing evidence blocks private calls.
- Endpoint allowlist contains only GET account/openOrders. One attempt only,
  bounded timeout and cancellation. The 1 MiB response cap is enforced while
  streaming with at most one extra discriminator byte; chunked bodies are stopped
  without allocating or reading the remainder. No unsafe retry.
- Production transport owns a `SocketsHttpHandler` with `AllowAutoRedirect=false`
  and rejects redirect responses, so `X-MEXC-APIKEY` cannot be forwarded to a
  redirected origin by the client.
- API keys are bounded to 256 printable ASCII bytes; CR/LF, non-ASCII, empty and
  oversized values are rejected before request creation, and header insertion must
  succeed. The unavoidable managed header string is bounded and lives only until
  the internal request is disposed.
- Time synchronization and bounded audit use synchronized state; all timestamp
  subtraction/midpoint/offset/addition operations are checked and fail closed.
- Typed masked state/audit and compact `MEXC PRIVATE · KEY REQUIRED` UI; balances
  are not displayed.
