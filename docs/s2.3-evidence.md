# TRDNG Stage 1 — S2.3 evidence

Дата: 2026-08-11. Статус: **IMPLEMENTATION / BUILD / PACKAGE PASS; TEST RUNTIME / VISUAL OPEN**.

Независимый аудит кода пройден без новых блокеров. Lifecycle относится только к
локальной simulation и не является биржевым transport/reconciliation.

## Результат

- Fail-closed lifecycle: `Confirmed → Submitted → Acknowledged →
  PartiallyFilled/Filled`, либо `Rejected`; timeout/transport loss → `Unknown`.
  Illegal, duplicate и out-of-order callbacks не продвигают state.
- Idempotency основана на `clientOrderId + SHA-256 immutable intent fingerprint`.
  Повтор exact submit возвращает существующую запись без второго события;
  мутация с тем же ID — hard conflict.
- `Unknown` не имеет auto-retry. Только explicit reconciliation evidence может
  перевести его в Acknowledged/Filled/Rejected; без evidence остаётся Unknown.
- Reconciliation использует structured evidence с exact clientOrderId,
  fingerprint, target state, свежим observedAt и непустыми source/reference.
  Journal хранит explicit transition kind и replay не доверяет тексту reason.
- Deterministic adapter реализует ack+fill, partial+fill, reject, timeout before/
  after ack и duplicate/out-of-order — без HttpClient/private transport.
- Append-only simulation journal хранит sequence, timestamp, exact fingerprint,
  state/reason и initial immutable intent; без secrets/tokens. File implementation
  пишет checksum envelope, `WriteThrough + Flush(true)`, допускает один truncated
  tail и отвергает corruption/sequence gaps в committed entries.
- Перед append незавершённый tail безопасно отрезается до последнего newline;
  journal sequence увеличивается только после успешного append, поэтому I/O fault
  не мутирует state и не создаёт gap.
- Journal имеет configurable hard cap и fail-closed overflow без недоказанной
  compaction. Lifecycle audit bounded и не содержит key/secret/token fields.
- Restart replay восстанавливает одну запись на clientOrderId; unresolved
  Submitted/Acknowledged/PartiallyFilled становится Unknown/RequiresReconciliation.
  Startup STOP остаётся engaged, автоматического продолжения нет.
- Desktop использует локально маркированный simulation journal; corruption/I/O
  переводит lifecycle в blocked fallback. После exact single-use confirmation UI
  предлагает только `ПРОИГРАТЬ СИМУЛЯЦИЮ` и показывает timeline. Unknown текст:
  `ТРЕБУЕТСЯ СВЕРКА · НЕ ПОВТОРЯТЬ`. История immutable при смене selection/input.
- Playback требует disengaged STOP. STOP или изменение selection/input очищает
  только active playable pointer, сохраняя immutable history. Любой ожидаемый
  runtime journal fault навсегда блокирует simulation в текущей сессии, включает
  STOP и не приводит к UI crash/retry.
- После replay timeline показывает recovered latest record либо
  `UNKNOWN · ТРЕБУЕТСЯ СВЕРКА`; active pointer отсутствует, STOP engaged.
